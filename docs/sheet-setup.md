# Google Sheet setup

One-time manual setup, performed by the repository owner in their own Google account.
Coding agents cannot perform or verify any of this — treat the sheet as an external
system with the contract described below.

## Contract the application relies on

- Worksheet named `Words` (case-sensitive, matches `SHEET_TAB`).
- Header row `A1:F1`: `id | term | translation | example | tags | added`.
- `id` is an **opaque string**. Never parse it, never sort by it, never assume a format
  or ordering. It is generated by Apps Script and is the only stable link between a sheet
  row and locally stored review progress.
- `term` and `translation` are required. `example`, `tags`, `added` are optional.
- `tags` is a comma-separated list.
- `added` is `YYYY-MM-DD`, filled automatically.
- Rows are appended at the bottom. Row order carries no meaning beyond the intake order
  of new cards.

## Sheet configuration

1. Freeze row 1 (`View → Freeze → 1 row`).
2. Protect `Words!A1:F1` — description `Header — do not edit`, permissions **only the
   owner**. Prevents a collaborator from renaming a column and silently breaking parsing.
3. Protect `Words!A2:A` — description `IDs — auto-generated`, permissions **only the
   owner**. Collaborators write to `B:E` only.
4. Publish to the web: `File → Publish to web → sheet: Words → format: CSV → Publish`.
5. Share the document with the tutor as **Editor**.

Do **not** use `Convert to table` (Google Tables). It changes the sheet structure and can
break the CSV export the application reads.

## Apps Script: id and date generation

`Extensions → Apps Script`, replace the contents with:

```js
const SHEET_NAME = 'Words';
const ID_COL = 1;      // A
const TERM_COL = 2;    // B
const ADDED_COL = 6;   // F
const HEADER_ROWS = 1;

function onEditInstallable(e) {
  const sheet = e.range.getSheet();
  if (sheet.getName() !== SHEET_NAME) return;

  const start = Math.max(e.range.getRow(), HEADER_ROWS + 1);
  const end = e.range.getLastRow();

  for (let row = start; row <= end; row++) {
    const term = String(sheet.getRange(row, TERM_COL).getValue()).trim();
    if (!term) continue;

    const idCell = sheet.getRange(row, ID_COL);
    if (!idCell.getValue()) idCell.setValue(newId_());

    const addedCell = sheet.getRange(row, ADDED_COL);
    if (!addedCell.getValue()) {
      addedCell.setValue(Utilities.formatDate(new Date(), 'UTC', 'yyyy-MM-dd'));
    }
  }
}

function backfillIds() {
  const sheet = SpreadsheetApp.getActive().getSheetByName(SHEET_NAME);
  const last = sheet.getLastRow();
  for (let row = HEADER_ROWS + 1; row <= last; row++) {
    const term = String(sheet.getRange(row, TERM_COL).getValue()).trim();
    if (term && !sheet.getRange(row, ID_COL).getValue()) {
      sheet.getRange(row, ID_COL).setValue(newId_());
    }
  }
}

function newId_() {
  return 'w' + Utilities.getUuid().replace(/-/g, '').slice(0, 10);
}
```

Then `Triggers → Add trigger`:

- function: `onEditInstallable`
- event source: **From spreadsheet**
- event type: **On edit**

### Why an installable trigger, not a simple `onEdit(e)`

A simple `onEdit` runs as whoever made the edit. The tutor has no write access to the
protected `id` column, so it would fail silently on exactly the edits that matter. An
installable trigger always runs as the owner who created it, regardless of who edited, so
it can write into the protected range.

### Why random ids, not sequential ones

Sequential ids require computing a maximum and can be reused after a row is deleted.
A reused id re-attaches existing review history to a different word — a silent, expensive
data corruption. Random ids make that class of bug impossible.

## Verification

Type a word into `B2` and its translation into `C2`. Within a second `A2` should contain
an id like `wa3f19c2b81` and `F2` today's date. If nothing happens, check
`Executions` in the Apps Script editor.

## Troubleshooting

| Symptom                                   | Cause                                                  |
| ----------------------------------------- | ------------------------------------------------------ |
| `/api/words` returns HTML                 | Sheet is not published to the web                       |
| New rows missing an `id`                  | Trigger not installed, or installed as a simple trigger |
| Rows appear on `/health` as invalid       | Empty `term` or `translation`, or a renamed column      |
| Edits not visible in the app for minutes  | Google's publish cache; use the manual refresh (`?fresh=1`) |
